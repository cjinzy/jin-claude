# jin-ambition

계획을 더 크게가 아니라 더 높게·깊게·넓게. 출처: Felix Rieseberg, "How to be more ambitious" (2026-10).

**축 선택**: 인자 `$ARGUMENTS` 가 `altitude`·`depth`·`range` 중 하나면 그 축만, 비었으면 세 축 모두 적용한다.

**계획 반영**: 계획에 `## Ambition` 섹션 — 적용한 축마다 한 항목. 해당 없으면 `N/A — 이유`.

**공통 규칙**
- 결과 확인은 외부 판정자(테스트·벤치마크·지표·원데이터 재현). 모델 자기 평가 금지.
- 범위 결정은 사용자 몫. 이미 정했으면 다시 묻지 않는다.
- 역할극·페르소나 연기 금지. 그 직업처럼 *쓰지* 말고 그 직업이 *하는 일*을 한다.

## Altitude — 작업이 아니라 결과를 맡긴다
1. 목표 너머의 목표를 2–3단 사다리로 쓴다 (각 단 한 줄, 아래에서 위로).
   - 예: 크래시 하나 수정 → 이번 릴리스 크래시 0 → 앱이 항상 크래시 없게 유지.
2. 어느 단으로 계획할지 AskUserQuestion 으로 묻는다 (원래 작업 포함).
3. 고른 단을 사람 없이 유지하는 전제조건을 점검한다:
   - 접근: 데이터·로그·리포트를 모델이 직접 가져오는가
   - 매핑: 결과를 원인(버전↔커밋, 지표↔이벤트)에 잇는 방법
   - 재현·검증: 모델이 혼자 재현·수정·확인할 환경
4. 부족한 것은 계획의 첫 단계로 둔다 (권한·도구 확보가 먼저).
- 반영: 고른 단, 성공 기준, 전제조건과 부족분. N/A 예: 창작, 단발성 작업.

## Depth — 더 큰 작업이 아니라 더 깊은 작업
1. 네 질문에 각 한 줄로 답한다:
   - 이 분야 최고 전문가는 요청받지 않은 무엇을 하는가?
   - 가공된 요약 대신 어떤 원자료에서 시작하는가?
   - 어떤 방법·도구를 쓰는가? (말투가 아니라 도구를 바꾼다 — markdown 표 대신 DB·통계 모델, 감 대신 프로파일러)
   - 너도 나도 아닌 무엇이 결과가 맞다고 보여주는가?
2. 핵심 가정 하나를 원자료로 반증 시도하는 단계를 넣는다 ("이탈은 온보딩 문제다" → 원로그로 재현).
3. 원자료 안에 이미 있다면 아직 모르는 신호를 찾고, 보지 않은 데이터로 예측력을 검증한다.
- 목표를 높이는 것은 외부 판정자가 있을 때만 — 없으면 거짓 완료가 된다.
- 반영: 4개 답, 반증할 가정, 외부 판정 방법. N/A 예: 사소한 수정.

## Range — 평소라면 비싸서 안 썼을 분야를 동원한다
1. 명사 → 동사: 산출물이 아니라 하는 일로 다시 쓴다.
   - 예: "분기 덱" → "바쁜 사람이 30분 안에 인과를 믿고 불확실한 상황에서 결정하게 만들기".
2. 팀 구성: 분야 2–4개 + red team 1개 (예: 분석가·기자·편집자 + 공매도 투자자·포렌식 회계사).
3. 분야마다 그 분야가 실제로 하는 일(기법·도구) 한 줄.
   - 나쁨: "공매도 투자자처럼 써라" / 좋음: "약점 가설을 세우고 반증 자료를 찾는다".
4. 채택할 기법을 AskUserQuestion(복수 선택)으로 고르게 한다.
- 반영: 동사 재서술, 채택한 분야·기법, red team 단계. N/A 예: 분야가 명확한 단순 작업.
