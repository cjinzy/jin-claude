# jin-depth

더 큰 작업이 아니라 더 깊은 작업. 출처: Felix Rieseberg, "How to be more ambitious" (2026-10).

## 절차

계획을 쓰기 전에 네 질문에 각 한 줄로 답한다:
1. 이 분야 최고 전문가는 사용자가 요청하지 않은 무엇을 하는가?
2. 이미 가공된 요약 대신 어떤 **원자료**에서 시작하는가?
3. 어떤 **방법·도구**를 쓰는가? (말투가 아니라 도구를 바꾼다 — 예: markdown 표 대신 DB·통계 모델, 감 대신 프로파일러)
4. 너도 나도 아닌 **무엇이** 결과가 맞다고 보여주는가? (테스트, 벤치마크, 원데이터 재현, 외부 도구)

그다음 계획에:
- 핵심 가정 하나를 골라 **원자료로 반증 시도**하는 단계를 넣는다. ("이탈은 온보딩 문제다" → 원로그로 재현해 본다)
- 이미 원자료 안에 있다면 아직 모르는 신호를 찾는 단계를 넣는다 (보지 않은 데이터로 예측력 검증).

## 계획 반영 (`## Ambition` → Depth)
- 4개 답 + 반증할 가정 + 외부 판정 방법.
- 목표를 높이는 것은 외부 판정자가 있을 때만. 없으면 "성공" 을 확인할 수 없어 거짓 완료가 된다.
- 해당 없음 (사소한 수정) → `N/A — 이유`.
