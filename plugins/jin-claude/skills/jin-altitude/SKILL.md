# jin-altitude

작업이 아니라 결과를 맡긴다. 출처: Felix Rieseberg, "How to be more ambitious" (2026-10).

## 절차

1. **목표 너머의 목표**를 2–3단 사다리로 쓴다. 각 단 한 줄, 아래에서 위로.
   - 예: 크래시 하나 수정 → 이번 릴리스 크래시 0 → 앱이 항상 크래시 없게 유지.
   - 예: 분기 덱 숫자 갱신 → 시급한 결정 3개와 찬반 → 문제를 더 빨리 잡는 리뷰 방식 설계 + 과거 데이터로 증명 + 한 분기 병행.
2. 사용자에게 어느 단으로 계획할지 묻는다 (AskUserQuestion, 원래 작업 포함). 사용자가 이미 정했으면 생략.
3. 고른 단을 **사람 없이** 유지하려면 무엇이 있어야 하는지 점검한다:
   - 접근: 데이터·로그·리포트를 모델이 직접 가져올 수 있는가
   - 매핑: 결과를 원인(버전↔커밋, 지표↔이벤트)에 잇는 방법
   - 재현·검증: 모델이 혼자 재현하고 고친 뒤 확인할 환경
4. 부족한 것은 계획의 **첫 단계**로 둔다 (권한·도구 확보가 먼저).

## 계획 반영 (`## Ambition` → Altitude)
- 고른 단, 성공 기준, 사람 없이 돌리기 위한 전제조건과 부족분.
- 결과 확인은 외부 판정자(지표·테스트·원데이터)로. 모델 자기 평가 금지.
- 해당 없음 (창작, 단발성 작업) → `N/A — 이유`.

## 하지 않는 것
- 사다리를 끝까지 올리라고 강요하지 않는다. 범위 결정은 사용자 몫.
